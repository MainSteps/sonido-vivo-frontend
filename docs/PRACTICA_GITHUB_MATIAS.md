## Flujo que Matías debe poder explicar

1. **Issue:** se revisa el objetivo y los criterios de aceptación de la tarea.
2. **Rama:** se actualiza `main` y se crea una rama con un nombre relacionado, sin trabajar directamente sobre `main`.
3. **Cambios y pruebas:** se implementa únicamente el alcance del issue y se comprueban el flujo normal y un caso límite.
4. **Commit:** se guarda una unidad de trabajo con un mensaje breve y coherente, por ejemplo `feat: implementar carrito y persistencia local`.
5. **Push:** se publica la rama en el repositorio remoto.
6. **Pull Request:** se solicita integrar la rama, se relaciona el issue, se explican las pruebas y se declara el uso de IA cuando corresponda.
7. **Revisión y fusión:** el equipo revisa el cambio y lo fusiona a `main` solo cuando las comprobaciones pasan.
